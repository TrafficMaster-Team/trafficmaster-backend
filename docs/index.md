# TrafficMaster Documentation

Welcome to the documentation for **TrafficMaster**, an asynchronous backend for learning traffic rules with spaced repetition.

## Project Overview

TrafficMaster provides the backend for organizing learning cards into decks and scheduling reviews for each user. The application exposes a REST API built with FastAPI and keeps learning progress independent for every user and card.

The project follows Clean Architecture principles with dependency inversion, explicit application use cases, and infrastructure adapters isolated from the domain model.

### Key Features

- **Spaced Repetition**: review queues, interval previews, ratings, progress, and review history.
- **Deck Management**: private and public decks with user-defined scheduling configurations.
- **Card Management**: questions, answers, images, tags, and deck assignment.
- **Authentication**: server-side sessions with signed JWT cookies.
- **RESTful API** powered by FastAPI and documented with OpenAPI.
- **Clean Architecture** with separate domain, application, infrastructure, and presentation layers.
- **Persistence** with PostgreSQL, SQLAlchemy, and Alembic.
- **Caching** through an optional Redis cache-aside layer.
- **Dependency Injection** using Dishka.
- **Comprehensive Testing** with Pytest and Testcontainers.
